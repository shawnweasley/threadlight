# 实现结构

```text
只读 Codex SQLite / 有界日志事件头 ─┐
                                  ├─ LocalMonitor → Reading[] → ActivityLedger
只读 Claude Code 进程状态 / 聚焦时间 ┘                          │
                                                        DisplayRow[]
                                                            │
                                        菜单栏 / 稳定原生菜单 / 置顶列表
```

## 模块

| 文件 | 职责 |
| --- | --- |
| `Domain.swift` | 客户端标识、读取结果、展示状态、稳定编号和完成确认 |
| `HeaderScanner.swift` | 只识别行首事件信封与事件类型，支持可选 ordinal |
| `TailStore.swift` | 每个日志最多 64 KB 的增量读取、截断/换文件处理和游标持久化 |
| `LocalSources.swift` | 只读 SQLite、桌面已读身份、小型 JSON 状态、Claude 聚焦时间 |
| `AgentApplication.swift` | 后台轮询、主线程绘图、偏好与生命周期 |
| `SignalArtwork.swift` | 菜单栏排布、状态图标和圆环帧 |
| `TaskSurfaces.swift` | 原生菜单条目稳定更新、浮窗横向缩放和响应式列表 |
| `PreviewExport.swift` | 使用合成数据绘制公开演示图 |

## 状态约定

1. 对话由「客户端 + 客户端会话 ID」确定，Codex 与 Claude 编号独立。
2. 初次发现运行中的对话时分配一个编号；同一客户端列表仍有对话时，编号保持稳定，新对话继续递增，不补空号。
3. 观测到结束事件后转为完成状态；停止或取消也算这一轮结束。
4. 已确认查看的完成对话隐藏；同一批次内下一轮工作沿用编号。某客户端列表全部清空后结束这一批，下一批从 `1`（Codex）或 `α`（Claude）重新开始，两个客户端互不影响，无需重启应用。
5. 丢文件、查询暂时失败、半行或未知事件不会触发虚假的完成；没有活动超时判定。
6. 首次启动不导入历史完成任务；两次轮询间开始并结束的新任务可由新的完成事件发现。

编号重置只清除旧批次的编号分配，仍保留已确认的状态和事件时间，防止再次读取旧完成事件时误当作新任务。若同一轮检查中最后一个旧对话移除、又发现新对话，则先结束旧批次再给新对话编号。

Codex 的 `task_started` / `task_complete` 等事件直接确定状态；有界尾部看不到开始事件时，`token_count` 或推理/工具调用事件头可确认仍在工作。`item_completed` 不等于整轮完成。记录必须以换行结束才可更新状态；大段正文不会跨轮保留在内存中。

## 刷新与性能

状态轮询为每 0.5 秒一次，前一次尚未完成则跳过；所有 IO 归一个后台队列。UI 主线程只消费小型状态结果。24 个圆环帧缓存以 20 fps 轮播，全部结束或开启减少动态效果后停用动画计时器。偏好/缓存不会写入被监控应用目录。

菜单在打开前确定结构，跟踪鼠标期间只原位更新文本与图标。新任务与移除任务在下次开菜单时重排；菜单栏和置顶浮窗继续实时同步。这样底部命令不会在指针下移动。

固定浮窗高度随任务数量调整，超过上限则滚动。左右边缘可调宽度；窄于 270 点隐藏右侧状态列。左侧状态图标始终保留，标题用原生尾部省略，不预先把字符串截短。

## 已知边界

- 默认最多检查最近 32 个候选对话，及本应用已经跟踪的对话。若首次启动时同时运行的对话多于 32 个，较早的活跃对话可能不被发现。
- 不读取远程主机或云端的状态，也不会启动后台 RPC 服务。
- 本地事件格式或认证身份格式变化可能需要更新适配器；无法确认时保留状态。
- Claude 以系统 PID 存活及小型会话状态为基础；异常残留文件、PID 复用或未写状态可能影响准确性，不把它当成系统进程审计工具。
- Claude 状态文件短暂缺失或未写完整时，保留上次状态；只有已观察到的进程全部退出，才根据缺失文件确认结束。
- 因未额外读取正文，极长单行占满尾部且没有可识别事件时，首次发现可能需要等下一条状态事件。
